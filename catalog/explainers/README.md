# Explainers: the prose of each catalog page

Every chemistry has a documentation page, `docs/catalog/<id>.md`, generated by
`tools/gen_catalog_pages.py`. The page combines two sources:

- `catalog/chemistries/<id>.yaml`, the specification: parameters, the formal
  (S, R, A) model, decisions, sources. This part is generated, so it cannot
  drift from the library.
- `catalog/explainers/<id>.md`, this directory: the hand-written prose that
  tells a reader what the chemistry is, how it works, how to use it and what
  has been done with it.

Edit these files, never `docs/catalog/*.md` (it is overwritten). Rebuild one
page with

    uv run python tools/gen_catalog_pages.py --only <id>

`ccm.md` is the reference example: read it next to its generated page before
writing a new one.

## Who the page is for

A reader who knows some science and some programming, but has never met this
chemistry and may know little chemistry. They should be able to read the page
from top to bottom and understand it. Everything comes with its context: what
a thing is and why it matters before how it is specified. Every term, symbol
and acronym is explained the first time it appears.

## File format

Four required sections and one optional one, as `## ` headings, in this order:

```markdown
## Introduction
## How it works
## Using it
## Results
## Further reading      (optional)
```

- No `# ` title: the generator writes it. No text before `## Introduction`.
- Use `### ` and `#### ` subheadings inside a section when it helps.
- There is no maths renderer. Write formulas in plain text, Unicode (×, ², →,
  ≤, Σ) and `inline code`, not LaTeX.
- Put species, reactions, parameter names and anything containing `<` or `>` in
  backticks. Put reactions or program output in fenced code blocks.
- Link to other chemistries by file name: `[the Brusselator](brusselator.md)`.
- The generator checks the format and refuses to build on unknown, repeated,
  missing or out-of-order sections.

## What the generator puts around your text

The page has four parts: **Introduction**, **How it works**, **Results**,
**References**. Write each section knowing what comes next to it, so nothing is
said twice.

| page part | your section | then the generator adds |
|---|---|---|
| Introduction | `## Introduction` | an "at a glance" table: family, kind, constructive, fidelity, book section, capabilities |
| How it works | `## How it works` | **Formal specification**: the YAML's S, R and A, including their `notes` |
| | | **Using it in Chemart**: the call `chemart.generate_network("<id>", seed=1)`, its `net.summary()` and first eight reactions, *then* your `## Using it`, then the **Parameters** table, then the **Implementation decisions** (collapsed) |
| Results | `## Results` | nothing |
| References | `## Further reading` | first the book section with its bibliography numbers, the links in `refs`, and **Sources used for the implementation** (the YAML's `sources`); then your further reading |

The YAML's top-level `notes`, `phenomena` and `intuition` are *not* printed on a
page that has an explainer. Whatever in them a reader needs belongs in your
prose.

## What goes in each section

### Introduction

What the chemistry is, in plain words, and why it exists. Who proposed it,
when, and what question or problem it was built for. The central idea, made
concrete with an image or a small example. Where it sits: the book chapter, and
its relation to other chemistries in the catalog where that helps. No parameter
names and no implementation details. Two to five paragraphs.

### How it works

The mechanism, as a story a newcomer can follow. What the molecules stand for,
what a reaction does to them, and what the reactor (the simulation algorithm)
does with the population. Include at least one worked example taken from a
network you actually generated: paste the real reaction(s) or output and walk
through what happens, step by step. Explain every quantity and term that the
formal specification below will use, so that the specification reads as a
summary of what the reader already understands.

### Using it

How to use the generator. The default call and its output are printed just
above your text, so start from them. Say what the default run is (which
published experiment, if any, it reproduces) and how to read the result: the
fields of `net.extras` that matter, what the species names mean. Then give
recipes: the parameter settings for each published experiment or interesting
regime, with code you ran and its real output. Say which settings are slow. Do
not repeat the parameter table, which follows your text; point into it instead.

### Results

What has been done with the chemistry. The main published findings, each in
context: what was measured or simulated, what was found, and why it mattered.
Give the numbers, figures and tables, checked against the sources. Include
later work that built on it where the book or the sources describe it. Every
item of the YAML's `phenomena` must be covered, and for each one say whether
Chemart reproduces it: read `tests/chemistries/test_<id>.py` and name what the
tests check. Be plain about what Chemart does not reproduce and why (the
`decisions` usually say).

### Further reading (optional)

Works mentioned in your prose that are not already in the YAML's `sources`, and
genuinely useful links, as a list with full citations.

## Accuracy

These pages are cited. Every factual statement must come from something you
have read or run: the book text, a source paper, the YAML and its decisions,
the generator code and tests, or your own runs of the generator.

- Never invent a motivation, an etymology, an anecdote, a number or a quote.
  If a source does not say why the author did something, do not say why.
- Quote only text you have seen, word for word, and say where it is from.
- Check every number against its source. The book, the papers and the catalog
  have all been wrong before. When they disagree, follow the YAML's
  `decisions`, and say so if the disagreement matters to the reader.
- Every code example must be one you ran, with its actual output.
- If you cannot verify something, leave it out.

## Style

Plain English, short paragraphs, active voice. Concrete before abstract:
an example first, then the general rule. Define jargon at first use, and
explain acronyms. No filler or hype ("powerful", "fascinating", "elegant",
"it is worth noting"). Name people and papers as "Kanada and Hirokawa (1994)"
in the text; the full citations are in the references. Length follows the
chemistry: a simple kinetic model may need 700 words, a rich one 2,500.
